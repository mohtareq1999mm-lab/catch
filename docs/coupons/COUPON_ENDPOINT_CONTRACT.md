# Coupon REST Endpoint Contract (every endpoint, §13 template)

> Evidence tags: [ROUTE]=live `route:list -v` · [SRC]=source read this session · [PRIOR-RUNTIME]/[PRIOR-TEST]=prior-session proof, not re-executed here unless stated.
> Envelope (all `apiResponse` controllers): `{status, message, success, data?}`. REST vs INTERNAL is labeled per stage; anything not listed under a stage does NOT happen for that endpoint.

## Global rules
- AUDIENCE (who enters distribution/discovery) ≠ ELIGIBILITY (who may use RIGHT NOW). Notification ≠ permission; available-feed ≠ checkout guarantee; `coupon.assigned` ≠ permanent validity.
- `audience_type`: PUBLIC (no assignments, no targeting) · ASSIGNED · TARGETED · ASSIGNED_AND_TARGETED — computed by `CouponAudienceResolver`, exposed on admin `CouponResource` + `targeting_mode`. `Coupon::isPublic()` ("no assignment rows") is frozen and is NOT the full classification.
- Mode truth table [PRIOR-TEST/RUNTIME]: `assignment`=grant required, rules ignored · `dynamic`=rules decide, grants ignored · `assignment_and_dynamic`=both must pass · `assignment_or_dynamic`=either qualifies. Consequences: assignment exists + rule fails → pass only in `assignment`/`assignment_or_dynamic`; rule passes + no grant → pass only in `dynamic`/`assignment_or_dynamic`; quota exhausted or grant expired → grant leg fails (fails `assignment`, `assignment_and_dynamic`; `assignment_or_dynamic` falls back to rules); claim/apply/checkout re-evaluate the SAME engine every time (no cached pass).

## 2. `POST /api/v1/coupons` — coupons.store [ROUTE+SRC]
